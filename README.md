# Stepwise

Планировщик поступления для школьников из Казахстана и Центральной Азии.

## Проблема

Абитуриент в одиннадцатом классе не знает, что уже потеряно. Дедлайн подачи в
январе выглядит далёким, но регистрация на экзамен, который нужен для этой
подачи, закрывается в ноябре — и когда человек впервые открывает сайт вуза, он
уже опоздал, не сделав ничего неправильного.

Существующие сервисы отвечают на вопрос «куда поступать». Этот отвечает на три
других:

```
Какие пути ещё открыты?
Когда каждый перестанет быть достижимым физически?
Что сделать прямо сейчас, чтобы не потерять варианты?
```

## Решение

Единица продукта — **путь (дверь)** с точкой невозврата. Для каждой программы
движок строит цепочку обязательных шагов **назад от дедлайна подачи** и
вычисляет последний день, когда путь ещё можно собрать. Доска сортируется по
срочности, а не по рейтингу вуза.

Чего продукт **не делает** принципиально:

- не считает вероятность поступления и не показывает «шансы»;
- не придумывает даты: если данных не хватает, путь получает статус
  `needs_data`, а не правдоподобную дату;
- не конвертирует валюты без курса;
- не решает за человека, какой вуз «лучше».

## Стек

Next.js 16 (App Router) · React 19 · TypeScript (strict) · Tailwind 4 ·
Zustand + persist · Zod · Vitest · motion.

Базы данных нет. Бэкенда с состоянием нет. Аккаунтов нет.

## Архитектура

```
Profile (localStorage)
   ↓
Match      — подходит ли путь: жёсткие ограничения отдельно, мягкий счёт отдельно
   ↓
Schedule   — обратное планирование от дедлайна → точка невозврата
   ↓
Door       — статус, дата, цепочка шагов, объяснение
   ↓
Route      — доска, отсортированная по срочности + сводка
   ├── Leverage     — что одно изменение профиля откроет
   ├── Diff         — что изменилось между двумя расчётами
   └── Next action  — ровно одно действие
   ↓
Zustand → persist → localStorage["stepwise-storage"]
```

Движок (`lib/engine/`) — чистый TypeScript: ни сети, ни часов, ни React, ни
модели. `today` передаётся аргументом, поэтому сервер, браузер и тест дают один
и тот же результат. Данные каталога — статические типизированные модули в
`data/`.

| Модуль | Отвечает за |
|---|---|
| `lib/engine/schedule.ts` | обратное планирование, точка невозврата |
| `lib/engine/match.ts` | соответствие профилю, жёсткие ограничения |
| `lib/engine/route.ts` | сборка доски, сортировка, сводка |
| `lib/engine/leverage.ts` | перебор изменений профиля |
| `lib/engine/diff.ts` | сравнение двух досок |
| `lib/engine/next-action.ts` | выбор одного следующего шага |
| `lib/engine/questions.ts` | выбор следующего вопроса интервью |
| `lib/engine/profile-patch.ts` | применение изменения к профилю |
| `lib/state/app-store.ts` | всё состояние приложения |

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
```

Проверки:

```bash
npm run typecheck
npx vitest run
npx eslint
npm run build
```

Мобильная проверка в настоящем браузере (Chrome с машины, без загрузки
браузера в node_modules):

```bash
npm run build
npx next start -p 3123
node scripts/mobile-qa.mjs     # 360 / 390 / 430 px, скриншоты в public/qa
```

Скрипт падает, если появилось горизонтальное переполнение, если кнопка ниже
32px или если экран вообще не отрисовался.

## Сценарий проверки

```
/            → лендинг
/start       → свободный текст + 5–7 адаптивных вопросов
/diagnostics → что известно, чего не знаем, правка любого поля
/doors       → доска путей по срочности, быстрая правка условий, leverage
/doors/[id]  → точка невозврата, что её определяет, цепочка шагов, источники
/compare     → два пути по осям решения
/roadmap     → шаги по месяцам, сколько путей держит каждый
/next-action → одно действие
/sources     → источники и методика
```

Ключевая демонстрация: на `/doors` изменить бюджет → доска пересчитывается на
устройстве мгновенно → открывается «Что изменилось» с тем, что открылось,
закрылось и как сдвинулся следующий шаг. Перезагрузка страницы сохраняет
профиль, доску и отмеченные шаги.

Полный путь целиком покрыт тестом `tests/judge-scenario.test.tsx`.

## Профили

Внутри браузера может жить несколько профилей. Это **не аккаунт**: пароля нет,
сервера нет, на другом устройстве профиля не будет — имя это ярлык на коробке
с ответами, и экран входа говорит это прямым текстом.

    stepwise-profiles          кто есть и кто активен
    stepwise-storage:<id>      отдельный ящик на каждого

Появилось из-за конкретной потери данных: «посмотреть на демо-профиле»
записывалось поверх единственного профиля, и вернуться было некуда. Теперь демо
стоит рядом, а не сверху.

| Файл | Отвечает за |
|---|---|
| `lib/state/profiles.ts` | реестр: чистые операции, ни часов, ни `window`, ни случайности |
| `lib/state/profile-session.ts` | переключение ключа хранилища — единственное место, где важен порядок |
| `lib/state/profile-store.ts` | текущее состояние для экранов |

Порядок в `activateSlot` не косметика: persist пишет при любом изменении
состояния, поэтому «сначала переключить ключ, потом очистить стор» записало бы
пустой профиль поверх настоящего. Сначала читаем коробку, потом переключаем.

Состояние, записанное до появления профилей, **усыновляется**, а не копируется:
слот указывает на старый ключ, поэтому один набор ответов не превращается в два.

## Оформление

Лендинг заморожен вместе с `app/globals.css`, поэтому палитра приложения живёт
в `styles/app-theme.css` и действует только внутри `.stepwise-app`. Tailwind
резолвит `bg-card` в `var(--card)` в месте использования, так что переопределения
подхватываются всеми существующими утилитами — ни один класс в компонентах
менять не пришлось, а главная страница рендерится ровно тем же CSS, что и раньше.

Цвет по-прежнему значит одно: насколько близко путь к закрытию. Мята — открыто,
янтарь — закрывается, коралл — последний шанс. Статус живёт на левой кромке
карточки: в колонке кромки складываются в читаемый градиент срочности.

На `/doors` сводка: счётчики, кольцо и шкала «когда закрываются» по месяцам. Всё
из `route.summary` и самих дверей — ни одного числа, написанного в разметке.
Процентов на экранах нет намеренно: «81 %» рядом со словом «открыто» читается
как шанс поступления, а такого числа в продукте не существует.

## Данные и источники

Каталог настоящий: **75 вузов в 19 странах, 85 источников, 10 действий**. Он
собирается детерминированным импортом из `data/raw/universities_verified.json`:

```bash
node scripts/import-universities.mjs              # → data/catalog.generated.ts
node scripts/import-universities.mjs --explain mit  # как прочитан один вуз
```

Сырой файл лежит в репозитории, поэтому любую дату на экране можно проследить
до предложения, которое опубликовал вуз. Импорт — единственное место между
ними, и он намеренно скучный.

Сложность в том, что сроки опубликованы прозой: «Early Action — 1 ноября
(решение в середине декабря). Regular Action — 4 января. Тесты: до 30 ноября
для EA, до 31 декабря для RA. Финпомощь: 30 ноября (EA), 15 февраля (RA)».
Три правила делают это разбираемым без догадок:

1. **Считается только подача.** Дата решения, экзамена, взноса, досылки
   документов или подтверждения места — не срок закрытия пути, хотя в тексте
   она почти всегда стоит позже.
2. **Путь закрывается на последнем раунде подачи.** Ранний раунд — это
   возможность; продукт отвечает на вопрос, когда возможности не станет.
3. **Год берётся из текста** или выводится по циклу поступления (месяцы с
   августа — год до набора, остальные — год набора). Выведенный год помечается
   `derived`, а не `verified`: год наш, а не вуза.

Четыре уровня доверия — и каталог честно неоднородный:

| Уровень | Сколько | Что означает |
|---|---|---|
| `verified` | 23 | вуз назвал дату целиком, вместе с годом |
| `derived` | 38 | день и месяц из источника, год выведен по циклу |
| `last_cycle` | 8 | опубликован календарь прошлого цикла; новый вуз не объявил |
| без даты | 6 | срок прочитать нельзя → `needs_data`, а не догадка |

Шесть вузов остались без даты намеренно: четверо из них прямо пишут, что единой
даты нет. Экран показывает их формулировку и ссылку.

Источник без URL — это честное состояние, а не недоделка: ссылка появляется
тогда, когда человек реально открыл страницу. Придуманный URL хуже
отсутствующего, потому что выглядит проверенным.

`tests/data-integrity.test.ts` проверяет каждую запись каталога: уникальность
id, реальность дат, существование источника, ссылочную целостность цепочек
действий и то, что `verified` не появляется без URL и даты проверки. Отдельный
тест закрепляет дюжину дат, на которых парсер когда-то ошибался — регрессия
разбора не видна глазом: продукт всё так же показывает уверенную дату, просто
неправильную.

## AI

AI живёт **только на границах системы** и ничего не считает. Три маршрута,
больше нет:

```
POST /api/parse     свободный текст → поля профиля (+ противоречия, + уровни уверенности)
POST /api/explain   рассчитанные факты о двери → 2–3 предложения
POST /api/diff      рассчитанный diff → формулировка «что изменилось»
```

Что модель **не делает** — структурно, а не по инструкции: в схемах ответа
просто нет полей для даты, срока, счёта, количества путей и вероятности. Она
получает уже посчитанный результат и возвращает слова.

**Grounding.** Каждое число и каждая дата в сгенерированном тексте сверяются с
входными фактами (`lib/ai/grounding.ts`). Не сошлось — ответ выбрасывается и
показывается детерминированный шаблон. Проценты запрещены всегда: в продукте
нет ни одной величины в процентах, поэтому «%» в ответе означает выдуманную
меру. Поле `grounded` отражает результат проверки, а не намерение.

**Ретраи.** Невалидный JSON или ответ не по схеме — ровно одна повторная
попытка со строгой инструкцией и текстом ошибки. Второй промах — шаблон.
Операционные сбои (нет ключа, таймаут, 429, 5xx) не ретраятся вообще:
детерминированный ответ мгновенный и всегда доступен.

**Кэш.** Ответы кэшируются в `localStorage` по хэшу запроса
(`lib/api/ai.ts`). Кэш хранит только формулировки — двери, даты и счётчики
пересчитываются движком на каждый рендер и никогда не читаются из кэша.

**Ключ.** Читается только на сервере (`lib/ai/client.ts` с `server-only`).
`NEXT_PUBLIC_`-варианта нет, SDK в клиентский бандл не попадает, `.env.local`
в `.gitignore`. Включить локально: положить `ANTHROPIC_API_KEY` в `.env.local`.

**Без ключа продукт работает полностью.** Деградирует только язык: интервью
разбирает текст правилами, объяснения берутся из шаблонов. Это покрыто тестами
(`tests/ai-routes.test.ts`) и проверено в браузере на запущенном сервере без
ключа.

## Что готово

- детерминированное ядро: schedule, match, route, leverage, diff, next action,
  адаптивные вопросы, AI-граница — 253 теста;
- адаптивное интервью на 5–7 вопросов, которое останавливается само;
- разбор профиля с правкой любого поля;
- доска путей, детали пути, сравнение, план по месяцам, следующий шаг;
- «Что изменилось» после правки профиля;
- источники и методика;
- AI-граница: три маршрута, grounding, ретрай, кэш, полная работа без ключа;
- состояние в localStorage с версией схемы, миграцией и защитой от порчи;
- пять состояний экрана: loading, empty, error, no-data, offline;
- мобильная вёрстка, проверенная в браузере на 360 / 390 / 430 px.

## Ограничения

- Разбор прозы берёт последний раунд подачи. Там, где вуз публикует разные
  сроки для разных категорий абитуриентов — Karolinska прямо пишет, что
  казахстанцам нужен первый раунд, — каталог назовёт более поздний. Формулировка
  вуза лежит на карточке целиком, но правило её не читает.
- Расширение каталога требует человека, который откроет сайты вузов и впишет
  источники в `data/raw/`.
- Профили не синхронизируются: другое устройство — другой набор профилей, и
  очистка данных сайта стирает их вместе с ответами. Без сервера иначе никак, и
  продукт говорит об этом на экране входа, а не после потери.
- Живого вызова провайдера на этой машине не было: ключа нет, и путь «с
  ключом» покрыт тестами против подставного провайдера, а не реальным запросом.
- Сравнение показывает стоимость за год: длительности обучения в данных нет, и
  придумывать её ради «стоимости за весь срок» мы не стали.
- Точка невозврата зависит от качества данных о сроках. Там, где их не хватает,
  продукт честно отказывается считать.
